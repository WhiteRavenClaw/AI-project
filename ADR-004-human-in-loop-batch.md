# ADR-004: Batch decision-support и human-in-the-loop вместо автоматической закупки

- **Статус:** Accepted
- **Дата:** 2026-10-01

## Контекст

Можно построить систему как автономного агента, который сам создает заказы поставщикам, либо как decision-support инструмент. Для первого релиза данные и модели неизбежно будут неполными, а ошибка закупки имеет прямую стоимость.

## Решение

MVP работает в **batch + human-in-the-loop** режиме:

1. прогноз и рекомендации рассчитываются по расписанию/по кнопке;
2. пользователь видит quantity, confidence и reason codes;
3. пользователь принимает, изменяет или отклоняет рекомендацию;
4. решение пользователя логируется как feedback;
5. система не отправляет заказ поставщику автоматически.

Первичная интеграция — CSV/XLSX, а не 1С API.

## Причины

- резко снижает интеграционный риск;
- позволяет закончить MVP за учебный срок;
- ошибка не превращается автоматически в финансовую операцию;
- feedback пользователя создает данные для улучшения policy;
- batch соответствует частоте большинства закупочных циклов малого retail.

## Альтернативы

### Real-time online inference

Не дает существенной ценности для первой версии, но увеличивает инфраструктурную сложность.

### Автономная закупка

Эффектное demo, но требует зрелых guardrails, интеграций, прав доступа, лимитов и юридической ответственности.

## Последствия

- latency SLA может измеряться минутами, а не миллисекундами;
- проще rollback модели;
- recommendation acceptance/edit rate становится важной продуктовой метрикой;
- API интеграции переносятся после доказательства ценности.

## Пересмотр

После успешного пилота можно добавить создание черновика PO, затем — ограниченную автоматизацию только для low-risk SKU и в заданных лимитах.
